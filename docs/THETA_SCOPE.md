# 세타 데모 · PRD 구현 범위

버전: 0.8.0-theta
기준: PRD v0.4와 세타 추가 요청. 기존 에타의 범위를 계승한다.

## 요청과 구현

| 요구 | 구현과 완료 조건 |
|---|---|
| 교사 컴퓨터 | 교실 PC 클릭·전용 메뉴 → 바탕화면 → 9개 업무 프로그램. 기존 학교톡·개인 일정·평가·가정통신문을 같은 창에서 이용한다. |
| 스티커메모 | 제목·본문 자동 저장, 4색, 고정, 보관·복원, 최초 작성 및 수정 게임 날짜. 개인 메모는 공식 학생 기록에 자동 복사하지 않는다. |
| 공문 처리, PRD 16 업무·16.3 계획 | 공문 접수 → 요청·마감 확인 → 초안·붙임 → 상신 → 교감의 보완/결재 → 최종 제출. 마감은 일정표와 연결하며 처리 이력을 보존한다. |
| 회의록, PRD 16.10 | 실제 참석 완료 기록의 시간·장소·안건·메모·협의 내용·후속 준비를 초안으로 생성한다. 같은 회의의 문서를 중복 생성하지 않는다. |
| 명렬표·기타문서 | 실제 학생 목록과 고유 초상화·오늘 출결·역할을 표시. 명렬표 문서, 계획서, 수업자료, 빈 문서를 편집·저장·텍스트 다운로드한다. |
| 풍부한 대사 | 학생의 각 9주제에서 6개 시작 변형, 보호자 6개, 교직원 역할별 6개. 관계별 후속 발화 길이와 기존 2회 응답 흐름 유지. 장소별 32쌍과 작은 생활 사건 12종 추가. |

| 이름·그래픽 | 확대 이름 약 8.67px/짧은 가로 화면 8px. 기존 대비 정확히 2/3. 교사 PC 소품·학생 필기구·책상 아래 가방·시간 연동 벽시계 추가. 에타 앞 공간과 착석 비율 유지. |

## 플레이 규칙

- 공문은 주 2건, 6개 유형을 주차별로 순환한다. 공문 ID·수신·기한·상태·이력은 저장된다. 기한이 지나면 표시하되 미처리 업무가 사라지지 않는다.
- 상신 5분, 최종 제출/공람 2분. 검토는 원칙적으로 상신 후 게임 15분이며 퇴근 무렵에는 다음 근무일로 넘어간다. 마지막 날 늦은 상신은 거절한다. 수업 또는 일정과 겹치는 시간을 건너뛸 수 없다.
- 교감은 필요한 첨부 유형, 남은 [작성] 표시와 최소 본문을 검사한다. 자연어 내용을 실제로 이해하거나 행정·법률상 적합성을 판단하는 시스템은 아니다.
- 상신본은 그때의 본문과 붙임을 복사해 보존한다. 수정은 원본에 저장되고 재상신할 때 새 결재본으로 반영된다. 제출 완료를 반복하여 보상이나 시간을 중복 처리할 수 없다.
- 공문 처리로 학습준비물 예산 또는 교사 능력을 자동 지급하지 않는다. 준비물 구매·시설 수리·기초학력 목적 예산의 기존 구분을 유지한다.
- 메모 최대 100개, 문서 최대 200개. 파일은 게임 안의 텍스트 문서이며 외부 업로드나 임의 파일 실행은 지원하지 않는다. 개인정보 메모는 명렬표 첨부에서 제외한다.
- 학생·동료 말풍선은 장소별로 노출 이력을 저장하여 같은 문장이 계속 뜨지 않는다. 실제 보이는 인물끼리 말하고, 공간이 바뀌면 이어질 답말풍선을 취소한다. 또래 관계 변화는 같은 조합에 하루 한 번만 반영한다.
- 자유 이동의 난수는 연출용이며 저장된 출결·자리·능력에는 영향을 주지 않는다. 수업·이동 행사·모달 열림·일시정지의 기존 경계를 유지한다.

## 저장과 접근성

- schema 4와 기존 저장 키를 유지한다. 이전 버전의 저장에는 computer 필드만 기본값으로 추가한다.
- 한글 입력 중인 내용도 화면을 닫거나 프로그램을 바꿀 때 저장한다. 내용이 변하지 않은 메모·문서는 수정일을 갱신하지 않는다.
- 좁은 화면에서 프로그램 메뉴를 가로 스크롤하고 본문은 독립적으로 스크롤한다. 프로그램 제목은 공간을 넘기지 않으며 메모·공문·큰 글자는 줄바꿈한다. PC가 열려 있을 때 바깥 교실은 조작되지 않는다.
- 사용자 입력은 화면에 텍스트로 표시한다. 버튼은 키보드 포커스와 명확한 이름을 제공한다. 브라우저 뒤로가기는 PC 하위 화면에서 바탕화면으로 돌아오고 이후 PC를 닫는다.

## 검증과 한계

상태 모델 테스트와 실제 Three.js 장면의 이동·충돌·착석 테스트, 실제 UI 모듈의 DOM·CSS 흐름을 확인한다. 이 차수에는 실제 브라우저/WebGL 화면의 시각 검수를 실행하지 않는다.

가상 학교의 한 학기 초반 10주를 다루는 데모다. 실제 업무관리시스템, 실기관 결재·발송, 법정 문서 검증, 인사·전근·다음 해 기억, 전체 연간 행사·생존수영 등은 기존 범위 문서의 후속 과제로 남긴다. 모든 학교 상황을 완성했다는 의미가 아니다.
