# 요타 데모 구현 범위

버전: 0.9.0-iota. PRD v0.4 및 사용자의 요타 요청을 기준으로 한다. 기존 세타 저장은 schema 4를 유지하며 그대로 이어받는다.

## 요청과 구현

| 요청 | 실제 동작 |
|---|---|
| 3월 안에 학급교육과정 수립 | 학급업무에서 목표·학생 지원·교과별 방법/공간/준비물/평가일·창체 활동 작성, 초안 저장, 20분 확정, 게임 날짜가 붙은 변경 이력, 학교톡 공유, 개인 일정 마감, PC 계획서 생성 |
| 학생 이동 속도 완화 | 자유 이동 0.68–1.105 장면 단위/초, 자리 복귀 1.445. 모두 이전의 85%. 무작위 대기·8방향·충돌 회피를 유지 |
| 모바일 시간표를 스크롤 없이 | 전용 높이의 하루/주간 보기, 요일 탭, 8개 일과 칸 또는 40개 주간 칸. 세로/가로 및 낮은 화면 전용 배치, 큰 글자 상한. 전담 표시와 원래 과목명 접근성 라벨 |
| 교사 업무 구분 | 학급업무: 교육과정·평가·학생 지원·가정통신문·상담·선거·운동회·준비물·청소. 행정업무: 공문·업무분장 계획·회의·연수·시설 요청·문서. 교사 PC도 두 영역의 바로가기 제공 |
| 전체 게임 그래픽 개선 | 생성한 원목 질감과 표면 요철, 둥근 가구 모서리, 조명·공간별 그림자 범위, 캐릭터 얼굴·머리·옷 세부, 운동장 잔디 무늬·골대 그물. 기존 방 구조·팔레트·착석 비율 보존 |

## PRD 추가 구현

PRD 8장의 학교 기본 교육과정에 따른 학급 계획, 계획/변경/실시/보완의 구분과 창체 영역을 10주 데모에 적용한다. 평가·누가기록 요구와 연결하여 계획을 입력하는 것과 실제 학생 기록을 남기는 것을 분리한다.

- 3월 마감은 이번 사용자가 정한 게임 운영 규칙이다. 가상학년도 2030년 3월 마지막 등교일인 3월 29일에 일정을 둔다. 최초 요청·마감 임박·기한 경과의 학교톡은 각 한 번만 생성한다. 전국 공통의 법정 제출 기한으로 표현하지 않는다.
- 과목별 목표·방법·공간·준비물·학습 증거·점검일, 학급 중점과 학생 지원을 저장한다. 창체 자율·자치/동아리/진로 활동은 기존 창체 시간 안에 계획한다. 같은 시간을 영역마다 중복 합산하지 않는다.
- 계획 확정에는 수업과 회의가 없는 교실·교사연구실·교무실의 20분이 필요하다. 초안 저장·메뉴 전환·닫기·앱 숨김 때 작성 상태를 보존한다. 확정본은 별도 스냅샷으로 남고 최근 10개 수정본을 조회한다. 3월 이후 시작하는 이전 저장도 실제 날짜의 기한 후 보완으로 제출할 수 있다.
- 계획의 수업 방법·준비물·목표를 해당 교과 수업 선택창에 표시한다. 공간 계획은 방문 예약이나 수업 중 자동 이동을 일으키지 않는다. 디지털 수업의 실제 가능 여부는 기존 학교/기기 상태를 따른다.
- 시수 화면은 기본 주간 시간표를 데모 기간에 펼친 기본 계획, 운동회 대체를 반영한 변경 계획, 실제 `lessonResults`, 시간이 지났으나 실시 기록이 없는 차시를 각각 집계한다. 방과후·늘봄·기초학력지도·급식·아침활동을 정규 교과 시수에 더하지 않는다.
- 미실시 차시는 준비 시간 5분으로 앞으로 있을 같은 과목의 담임 수업에 핵심 목표를 연결한다. 해당 수업의 실제 기록이 생겨야 완료된다. 과거 기록을 소급 생성하거나 한 수업을 두 차시로 계산하지 않는다. 예정한 다음 수업도 놓쳤다면 재계획할 수 있다. 전담수업을 담임 보완 대상으로 예약하지 않는다.
- 과목별 평가 점검일을 개인 일정에 등록한다. 확정 목표와 학습 증거가 일치하는 수행평가 기록이 있어야 해당 학생을 점검 인원에 포함한다. 미실시는 제외하고, 현재 결석한 학생에게 새 평가 결과를 입력하는 것은 막는다. 이전에 실제로 기록한 평가 근거는 보존한다. 목표 또는 증거를 바꾸면 이전 근거로 새 계획을 자동 완료하지 않는다.
- 확인한 계획은 교사 PC에서 편집/내려받기 가능한 계획서로 만들 수 있다. 복사한 문서 수정이 확정된 교육과정 원본을 바꾸지는 않는다. 게임 학교톡으로 공유할 뿐 실제 학교 시스템에 접속하지 않는다.

## 그래픽 자산과 성능 선택

`dist/assets/oak-grain.png`는 이번 데모를 위해 생성한 1254×1254 원목 표면 이미지다. 평평한 중성 조명, 가는 무늬, 옅은 꿀빛/중성 참나무 색, 이음매·방향성 그림자·문자 없는 반복 표면을 요청해 생성했다. 원본 전체 이미지를 확인한 뒤 수정 없이 재질로 사용했다. 타사 학교 사진이나 인물 사진은 사용하지 않았다.

하나의 이미지 텍스처를 재질에 공유하고 UV 배율로 반복하며, 방을 옮길 때 그물의 geometry/material을 해제한다. 모바일 폭에서는 그림자 1024, 큰 화면에서는 2048 해상도를 사용한다. 출력 픽셀 비율 상한은 각각 1.6/2다. 복잡한 후처리나 실시간 외부 이미지 호출은 추가하지 않는다.

## 검증과 한계

89개 Node 검사로 저장 변환, 학년별 편성, 마감/확정/수정, 결석·미실시 구분, 시수 중복 방지, 보완 수업, 회의 충돌, 예산, 기존 활동을 확인했다. 실제 Three.js geometry와 이동 코드를 실행하여 가구 치수·착석 등받이 간격·이동/가구 충돌·속도·재질·그림자 범위·그물 자원 해제를 확인했다.

실제 앱 모듈을 DOM 환경에서 실행해 기존 PC/공문/회의/선거/운동회와 새 계획→PC 문서→평가 기록→시수 보완 흐름을 확인했다. 320×568, 390×844, 844×390, 1280×900의 100/200% 글자 설정에서 일과 칸 수, 주간 칸 수, 그리드 전환과 스크롤 컨테이너 CSS를 점검했다. DOM 환경의 숫자 option 초기 선택 파싱 차이는 테스트에서 HTML selected 속성대로 보정한다. 이는 실제 브라우저 픽셀 배치·실기기 성능·WebGL 화질을 확인한 검사가 아니다.

3월부터 다음 2월까지의 전체 학년도, 학년군 최소 시수/증감/학교자율시간/지역 규칙 검증, 성취기준 코드 매핑과 전체 평가 계획, 추가 차시 편성·교환과 전담 결강 보충, 실제 특별실 예약은 후속 범위다. 이번 장부는 데모의 계획과 실제 수업을 비교하며 법적 교육과정 적합성을 판정하지 않는다. 새 문서에 적은 창체 활동을 모두 별도 게임 사건으로 실행하는 기능도 아직 포함하지 않는다.
